Lightbox accessibility improvement for NVDA

Current issue

Testing the current lightbox pattern with users who rely on NVDA, has shown that instances occur that the user is unable to navigate through a lightbox (stuck the lightbox wrapper).

Principal Publisher solution

A focus key command using the space key was allowing NVDA users to focus within the dialog (lightbox).

Outstanding concern

Are NVDA users aware that they need to apply this action in order to read the dialog? NVDA does not announce the action needed to take in order to focus on the dialog.

Proposed solutions

Option 1

Use an announced aria-label in order to inform the screen reader user that a keyboard space press may be needed to focus inside the dialog.

The downside is that, although it doesn't affect JAWS or VoiceOver users, it's unnecessary for them to do this extra step.

Option two

Replace the spacebar focus command with a function that applies focus automatically to the header of the dialog after it opens. Will require a 100ms delay so the function run asynchronously.

This works with both dialogs open from content within the page, and those that are ajax'd in.

The downside is because JAWS and VoiceOver do not require the extra focus, the announcement of the header is repeated.
